## 1. “4종 의미 충돌” 표현 수정

기존 문구는 API 키가 없는 데모 결과를 전체 제품 규칙처럼 보이게 해 심사자가 불일치로 판단할 수 있었다.

수정 기준:

- **체험·데모 모드:** 성공 기준, 범위, 제약, 완료 조건의 표준 4유형을 항상 제공한다.
- **실제 AI 모드:** 요청의 직무·도메인·문맥에 따라 2~8건을 동적으로 탐지한다. 카테고리 이름도 결과마다 달라질 수 있다.
- 화면에 현재 모드와 실제 탐지 건수를 함께 표시한다.

심사 설명 문장:

> API 키가 없는 체험 모드는 안정적인 시연을 위해 표준 4유형을 제공하고, 실제 AI 모드는 문맥에 따라 2~8개의 의미 충돌을 동적으로 탐지합니다.

## 3. UI/UX 조치

결과를 한 번에 읽게 하지 않고 다음 순서로 확인한다.

1. **오해 진단:** 점수, 전달 흐름, Meaning Diff
2. **직무별 해석:** Role Lens
3. **실행 합의:** Shared Contract와 Decision Ledger
4. **이해 확인:** Receiver Receipt

점수는 전체 상태를 빠르게 보는 요약으로 유지하고, 상세 흐름 지도는 첫 탭에서만 노출한다. 로그인 없이 입력 → 진단 → 합의 → 확인의 로직을 바로 체험할 수 있다.

## 4. Vercel 배포 체크리스트

- [x] `/api` 엔드포인트를 Vercel Functions로 구성
- [x] Vite 결과물을 Vercel 정적 경로 `public/`에 빌드
- [x] `.env`와 로컬 산출물 업로드 제외
- [ ] Vercel 계정·GitHub 저장소 연결
- [ ] Production 환경변수 `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_MODEL` 등록
- [ ] Production 배포 후 `/api/health`에서 `aiMode: available` 확인
- [ ] 실제 요청 1건에서 `generationMode: ai` 확인
- [ ] 모바일·데스크톱에서 공개 링크 최종 점검

API 키는 프론트엔드 변수나 GitHub 저장소에 넣지 않고 Vercel 서버 환경변수로만 등록한다.

## 5. OpenAI 실호출 검증 결과

- 모델: 팀 공유 설정의 `gpt-4o`
- API: OpenAI Responses API + JSON Schema Structured Outputs
- 결과: `generationMode: ai` 확인
- 동적 탐지: 같은 샘플에서 3건과 4건이 각각 생성되어 고정 4종이 아님을 확인
- 언어 품질: 카테고리까지 한국어로 출력하도록 지시문 보강
- 역할 완전성: AI가 일부 Role Lens를 누락해도 모든 대상 직무가 결과에 포함되도록 서버 보정 추가
- 보안: 키 값은 로그·화면·Git에 출력하지 않음
